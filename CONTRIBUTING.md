# Contributing

Thank you for helping improve KPI. For substantial changes, open an issue first
to discuss the problem and approach. Do not include real employee data, tokens,
credentials, or private company information in issues, pull requests, fixtures,
or screenshots.

1. Fork the repository, create a branch, and follow the
   [local setup](README.md#local-development).
2. Keep changes focused, add tests for behavior changes, and update relevant
   documentation.
3. Run the applicable [tests and builds](README.md#tests-and-builds). Use only
   disposable databases for tests and demo data.
4. Open a pull request describing the change, how it was verified, and any
   migration or configuration impact.

Report security issues privately as described in [SECURITY.md](SECURITY.md).
